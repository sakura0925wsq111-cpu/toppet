# TopPet 实体 AI 桌宠产品文档

> 产品代号：TopPet / 老勺子
> 文档版本：v0.3
> 更新日期：2026-08-12
> 当前阶段：PC 原型已可运行，实体样机处于 EVT（工程验证）准备阶段

TopPet 是一款具有固定角色人格、表情反馈、语音对话和长期记忆能力的实体桌面陪伴设备。首发角色“老勺子”面向私人陪伴场景，通过 480×480 AMOLED 屏幕、触摸/按键、麦克风和扬声器完成自然交互。

本 README 同时作为产品需求文档、工程边界说明和样机验收基线。文中的“已实现”表示当前 Windows 原型已经具备；“目标”表示实体样机必须实现或验证，不代表当前硬件已经交付。

## 1. 产品定义

### 1.1 产品定位

TopPet 不是通用智能音箱，也不是运行在 ESP32 上的离线大模型设备。它是一款强调角色一致性、情绪表达和低学习成本的私人桌面陪伴产品：

- 用户通过按住说话、触摸或实体按键发起互动。
- 桌宠用表情即时展示“聆听、思考、说话、空闲”等状态。
- 电脑端完成语音识别、AI 推理、长期记忆和个性化声音合成。
- ESP32-S3 实体端负责交互采集、动画显示、音频播放、联网和电源管理。

### 1.2 目标用户

- 希望获得稳定、私密、具有专属人格陪伴体验的个人用户。
- 希望把自己的声音、称呼、共同记忆和角色形象做成礼物的制作者。
- 需要一个可继续扩展角色、表情、声音和硬件外壳的开发者。

### 1.3 核心价值

1. **角色稳定**：称呼、语气、声音、表情和长期记忆属于同一个角色，不因重启或切换功能而混乱。
2. **反馈明确**：每个耗时步骤都有视觉状态，用户始终知道设备正在聆听、思考还是播放。
3. **语音自然**：支持本地 Whisper 识别和 VoxCPM2 个性化声音，回复可按句流式合成与播放。
4. **隐私可控**：密钥和记忆保留在主机端；麦克风采集必须有清晰、同步的可见反馈。
5. **可维护**：角色配置、业务逻辑、语音引擎、硬件端和生成产物相互隔离。

### 1.4 MVP 范围

首个实体样机必须实现：

- 按住说话或触摸发起语音对话。
- `IDLE → LISTENING → THINKING → TALKING → IDLE` 完整状态闭环。
- 角色表情动画、AI 对话、本地时间/天气、个性化 TTS 和独立长期记忆。
- 2.4GHz Wi-Fi 下与一台常开 Windows 主机通信。
- USB-C 供电、锂电池供电、充电状态和低电量提示。
- 网络、模型或音频异常时可恢复，不因一次失败死机。

MVP 不包含：

- 在 ESP32-S3 上直接运行 Whisper、LLM 或 VoxCPM。
- 无主机、无网络条件下的完整动态对话。
- 摄像头、持续监听、自动录像或人脸识别。
- 未经用户确认的云端长期音频存储。
- 面向量产销售的认证结论。

## 3. 典型使用场景

### 3.1 首次启动

1. 用户为实体桌宠通电。
2. 设备完成屏幕、音频、存储和网络自检。
3. 未配网时进入配网引导；已配网时连接指定主机服务。
4. 主机服务健康检查通过后，设备显示角色问候并进入待机。
5. 任一依赖不可用时显示可理解的错误状态，不无限停留在“思考中”。

### 3.2 语音对话

1. 用户按住按键或屏幕上的说话区域。
2. 设备在 100ms 内切换到 `LISTENING`，并开始录音。
3. 用户松开后停止录音，将音频发送到主机。
4. 主机依次完成 ASR、对话推理、记忆读取和 TTS。
5. 回复文本按句返回，首段音频可播放时立即进入 `TALKING`。
6. 播放结束后回到 `IDLE`；记忆提取在后台进行，不阻塞下一次交互。

### 3.3 打断与恢复

- 在 `THINKING` 或 `TALKING` 状态再次按下交互键，当前请求和剩余音频应被取消。
- 新会话必须使用新的会话 ID；旧线程和迟到的数据包不得污染新回复。
- 网络短暂断开时显示离线状态并自动重连，不删除本地角色和配置。

### 3.4 私密模式

- 用户可关闭麦克风交互，只保留触摸、按键和状态展示。
- 清除记忆后，主机端对应角色的长期记忆文件应被删除或重置。
- 设备端不得保存 API Key、完整聊天记录或永久原始录音。

## 4. 交互与状态规范

### 4.1 主状态机

```text
BOOT ──自检通过──> IDLE
 │                 │
 └──失败──> ERROR  ├──按下/触摸──> LISTENING
                   │                  │
                   │              松开/结束录音
                   │                  ↓
                   │              THINKING
                   │                  │
                   │              首段音频就绪
                   │                  ↓
                   └────────────── TALKING
                                      │
                                  播放完成
                                      ↓
                                    IDLE
```

任意交互状态都允许进入 `ERROR`、`LOW_POWER` 或 `OFFLINE`。恢复后应返回 `IDLE`，而不是自动重放过期内容。

### 4.2 状态反馈要求

| 状态 | 屏幕反馈 | 声音/操作反馈 | 退出条件 |
| --- | --- | --- | --- |
| `BOOT` | Logo 或启动动画 | 默认静音 | 自检和服务探测完成 |
| `IDLE` | 中性或空闲动画 | 可接受交互 | 用户按下、定时空闲动作或低电量 |
| `LISTENING` | 明确的聆听表情与录音指示 | 松开即结束 | 松开、超时、取消或录音失败 |
| `THINKING` | 思考动画 | 允许打断 | 首段音频、取消、超时或失败 |
| `TALKING` | 说话/对应情绪动画 | 扬声器播放 | 播放结束、打断或播放失败 |
| `OFFLINE` | 网络断开图标，不冒充思考状态 | 可重试 | 主机服务恢复 |
| `LOW_POWER` | 电量不足提示 | 限制高耗电动画 | 接入电源或安全关机 |
| `ERROR` | 简短错误类别和重试入口 | 不循环播放提示音 | 重试成功或用户取消 |

### 4.3 角色一致性

- 人格、显示名、称呼、声音、表情和记忆文件必须由同一个角色配置派生。
- 角色切换不得复用另一个角色的长期记忆或待播放音频。
- 缺失表情首先回退到该角色的 `NEUTRAL`，不得随机加载其他角色资源。
- “老勺子”正式产品模式应使用经过授权的个性化声音。当前 EdgeTTS 回退仅用于开发期可用性；是否允许在成品中回退必须由产品配置显式决定，并给用户可见提示。

## 6. 软硬件架构

### 6.1 部署边界

```text
┌──────────────────────── 实体桌宠 ────────────────────────┐
│ ESP32-S3                                                  │
│ 屏幕/触摸/按键 · 麦克风采集 · 扬声器播放 · Wi-Fi · 电源 │
└───────────────────────┬──────────────────────────────────┘
                        │ HTTP/WebSocket（目标）
                        │ PCM/WAV、状态事件、文本、音频流
┌───────────────────────▼──────────────────────────────────┐
│ Windows 主机服务                                         │
│ 会话编排 · Faster Whisper · AI API · 长期记忆 · VoxCPM2 │
└──────────────────────────────────────────────────────────┘
```

ESP32-S3 不承担大模型推理。所有高算力任务保留在主机端，可以避免设备过热、续航过短和固件复杂度失控。

### 6.2 目标通信协议

- WebSocket：传递实时状态、会话事件、音频分片和取消指令。
- HTTP：健康检查、版本查询、配置读取和诊断下载。
- 每次交互必须包含 `device_id`、`character_id` 和唯一 `session_id`。
- 音频与文本响应必须携带会话 ID，设备丢弃已经取消或过期的会话数据。
- 服务只监听受信任网络接口；跨设备访问需要令牌，不能依赖“知道 IP 地址”作为认证。
- 协议需要版本号，主机与固件不兼容时给出明确升级提示。

### 6.3 当前软件模块

```text
toppet/
├── laoshaozi.py          # Windows 原型入口
├── core/                 # AI 客户端、对话、记忆、流式分句和应用编排
├── systems/              # 情绪、状态、角色映射和本地服务生命周期
├── audio/                # 录音、播放、ASR 和 TTS 引擎
├── ui/                   # PyQt6 原型界面与后台工作线程
├── common/               # 共享路径等无框架依赖能力
├── config/               # 角色档案和表情映射
├── assets/               # 角色、参考音频和本地模型资源
├── tests/                # 自动化测试和端到端 smoke 脚本
├── tools/                # 资源检查与 GIF 生成工具
├── docs/                 # 架构、声音和硬件资料
├── artifacts/            # 可重建的生成/调试产物，不提交 Git
└── logs/                 # 日志、本地记忆和 PID，不提交 Git
```

所有跨模块文件位置由 `common/paths.py` 统一定义，业务代码不得依赖启动时的当前目录。

## 7. 硬件基线

### 7.1 EVT 候选主板

| 项目 | 基线要求 |
| --- | --- |
| 主控与屏幕 | 微雪 `ESP32-S3-Touch-AMOLED-2.16` |
| 显示 | 480×480 AMOLED，支持触摸 |
| 网络 | 2.4GHz Wi-Fi；不假定支持 5GHz |
| 录音 | 板载双麦克风，目标输出 16kHz、16bit、单声道 PCM/WAV |
| 播放 | 板载音频链路；实体扬声器是否随套餐提供必须下单前确认 |
| 存储 | 板载 Flash；TF 卡作为资源缓存和诊断扩展项 |
| 电池 | 3.7V 1000mAh 候选电池，实际续航必须以整机测试为准 |
| 供电 | USB-C，5V 2A 电源基线 |
| 输入 | 电容触摸；三个实体按键为外壳交互候选方案 |

详细采购和到货测试见 [`docs/hardware-checklist.md`](docs/hardware-checklist.md)。

### 7.2 结构设计要求

- 外壳不得遮挡触摸有效区、麦克风开孔、出音孔、USB-C、电源键和散热区域。
- 电池需要绝缘、限位和缓冲，不得被螺丝、焊点或外壳锐边挤压。
- 麦克风与扬声器需要声学隔离，避免播放回声直接进入采集通道。
- 底座应具备防滑能力；正常触摸和按键操作不应导致设备倾倒。
- 后盖应可维护，避免使用必须破坏外壳才能更换电池或重新烧录的结构。
- 外壳表面和开孔不得存在可触及锐边；长期接触区域不得出现明显高温点。

## 8. 性能、可靠性与质量基线

以下均为实体样机验收目标，尚未实测的项目必须在 EVT/DVT 报告中记录结果，不能直接标记为完成。

| 类别 | 指标目标 |
| --- | --- |
| 交互反馈 | 按下或触摸后 100ms 内出现视觉状态变化 |
| 首段回复 | 主机模型已预热、局域网正常时，结束说话到首段音频开始播放的 P95 ≤ 8 秒 |
| 录音 | 安静室内 0.5–1m 正常音量讲话可稳定识别，无明显持续电流噪声 |
| 连续对话 | 连续 20 轮语音交互无崩溃、死锁、串话或过期音频播放 |
| 长稳运行 | 连续待机和间歇对话 8 小时，无不可恢复断线和明显内存增长 |
| 网络恢复 | Wi-Fi 或主机中断后 30 秒内进入明确离线状态；恢复后无需重启即可继续使用 |
| 动画稳定性 | 连续播放动画 30 分钟无黑屏、花屏、触摸漂移或明显掉帧 |
| 音频稳定性 | 连续播放 30 分钟无持续破音、啸叫或线程卡死 |
| 电池续航 | EVT 实测后冻结；首轮工程目标为典型交互 ≥ 2 小时 |
| 表面温度 | 25℃ 室温典型负载下，用户持续可触区域工程目标 ≤ 45℃ |
| 数据恢复 | 配置损坏、服务超时和意外掉电后可以回到配网/待机状态，不无限重启 |

性能数据必须注明：固件版本、主机配置、模型、网络条件、室温、电池状态和样本数量。

## 9. 安全、隐私与合规边界

### 9.1 电气与电池安全

- 仅使用带保护电路、极性和插头匹配的合格锂电池。
- 首轮充放电、温升和待机测试必须有人值守；异常发热、鼓包、异味时立即断电。
- 固件需要处理低电量、充电状态和异常掉电，避免反复深度放电。
- USB 电源、线材和外壳材料必须适合实际工作电流与温度。

### 9.2 隐私与数据

- API Key 只保存在主机环境变量或 Git 忽略的本地文件中，不写入固件、仓库或日志。
- 默认不永久保存原始录音；调试录音必须由用户主动开启并可删除。
- 长期记忆按角色隔离，用户可以查看和清除。
- 日志不得记录密钥、完整鉴权头或不必要的完整对话内容。
- 若 AI、天气或 TTS 使用第三方服务，产品界面和交付说明需要明确数据会离开本地网络。

### 9.3 商业化说明

本文是内部产品和工程验收基线，不构成认证或法规符合性声明。如果产品进入销售、运输或公开交付阶段，必须根据目标地区另行完成无线、电磁兼容、电气安全、锂电池运输、材料环保、隐私和内容合规评估，并保留测试与供应链文件。

## 10. 异常与降级策略

| 异常 | 产品行为 |
| --- | --- |
| 主机服务未启动 | 显示离线，引导检查主机；保留本地动画和设置 |
| ASR 无结果 | 提示“没有听清”，不发送空内容给 LLM |
| LLM 超时 | 取消当前会话，显示可重试状态，不永久停留在思考动画 |
| VoxCPM2 未就绪 | 根据产品配置等待、提示或使用授权回退声音；不得静默换成陌生声音 |
| 音频播放失败 | 清空当前播放队列并回到待机，允许立即开始新会话 |
| Wi-Fi 断开 | 停止上传，显示离线并指数退避重连 |
| 电量过低 | 停止高耗电任务、保存必要状态并安全关机 |
| 角色资源缺失 | 回退到当前角色中性表情，同时记录可诊断错误 |
| 配置文件损坏 | 使用最小安全默认值启动，并提供恢复出厂入口 |

## 13. 配置与扩展

角色由两份数据驱动配置组成：

- [`config/character_profiles.json`](config/character_profiles.json)：显示名、人格、UI 文案、声音和记忆文件。
- [`config/expression_mapping.json`](config/expression_mapping.json)：统一情绪到角色表情的映射。

新增角色需要：

1. 在角色档案中添加唯一角色 ID。
2. 添加情绪映射，不支持的情绪明确回退到 `NEUTRAL`。
3. 把 PNG/GIF 放入 `assets/characters/<角色 ID>/`。
4. 添加角色隔离、资源发现和 TTS 选择测试。
5. 确认所使用的形象、声音和训练数据具有授权。

软件模块边界详见 [`docs/architecture.md`](docs/architecture.md)。

## 14. 实体 MVP 完成定义

只有同时满足以下条件，才能把项目标记为“实体桌宠 MVP 完成”：

- 实物完成通电、充电、电池供电、屏幕、触摸、录音和播放测试。
- P0 功能需求全部通过并留有测试记录。
- 在目标主机与目标 Wi-Fi 环境中连续完成 20 轮语音对话。
- 用户能够分辨所有关键状态，并能随时取消正在进行的请求。
- 角色人格、声音、表情和记忆在重启、异常和连续会话中保持一致。
- 低电量、断网、模型超时、录音失败和播放失败都有可恢复行为。
- 外壳不存在明显锐边、挤压电池、遮挡声孔或不可维护的问题。
- API Key、录音和长期记忆符合本文的隐私要求。
- 已记录固件、主机软件、模型、配置和硬件版本，可复现交付状态。

在这些条件完成前，项目应标记为“软件原型”或“工程样机”，不能描述为已完成的实体产品。
