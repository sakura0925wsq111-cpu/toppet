# 大肥鱼：QQ 与实体硬件共用人格

本次修改完成后，硬件不再只有“简短口语”的通道提示。QQ 和硬件每轮使用同一份大肥鱼身份、性格和选中角色卡，保留各自的渠道交互规则。

## 唯一人格来源

默认人格源仍是 qq-bridge 原有的 `dsh/agent-presets/qq-chat-v2/agent.cordis.yml`，没有复制一份硬件人格文件。新增 `src/shared-persona.js` 统一读取其中的身份、“反 AI 味”和主体性段落，并叠加原有角色卡读取结果。

QQ 提示词投递、QQ 的 `qq_get_prompt` 和硬件提示词均调用同一提供者。即使没有选择角色卡，硬件也得到“大肥鱼 / DeepSeek 鲸鱼形象、有主体性、不充当客服”的默认人格。人格正文发生变化时两端校验值一起变化；硬件旧会话按既有机制退役，不清除桥接记忆。

QQ 原预设中的编码助手开场已改为说明人格由共同来源注入。硬件预设通过本机配置中已有的受管标记块升级，只更新渠道协议，其他 DSH 配置、MCP 注册与守卫配置字节保持不变；第二次执行安装脚本不再改写文件。

## 共用记忆与权限

两端使用 qq-bridge 原有的 `state/long-term/people.md`，个人记忆按同一 `QQ:<用户标识>` 分区读写。本人私聊中的默认 / QQ 号形式记忆名称归一到该分区，写入、读取和删除保持一致。近期私聊和硬件已确认播放的回复继续通过桥接共享。

没有新建 TopPet 聊天记忆，也没有调用 PetBrain。群聊与其他用户的记录不自动进入绑定用户的硬件上下文，智能体接口也不能跨会话读取或覆盖个人记忆分区。历史资料不清空，不将不确定归属的档案自动当作本人信息。

硬件专用工具守卫允许三项本轮硬件 / 个人记忆工具，以及 QQ 已有的两项安全网页工具：

- `hardware_reply`、`hardware_status`、`hardware_memory`。
- `mcp__web-search-safe__web_search`、`mcp__web-search-safe__web_fetch`。

仍拒绝 QQ 发送、QQ 长等待、本地命令、文件和普通 TopPet 控制工具。网页结果只是资料，不能赋予权限。网页工具的真实 stdio 查询检查已成功，经现有 Bing 回退路径返回结果；这项探针不是一次真实硬件天气问答验收。

## 实际验证

- 自动检查覆盖原文共享、修改单一来源后两端同时变化、角色卡一致、QQ 实际提示词投递、真实 HTTP 记忆路由、双向读写 / 删除及群聊隔离。
