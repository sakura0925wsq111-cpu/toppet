## 2. 目标与实现边界

大肥鱼明确指 [Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)。正常使用流程如下：

```text
桌宠按键录音
  → TopPet Whisper 识别
  → qq-bridge 硬件入口
  → 绑定用户、现有人格、个人记忆、私聊背景
  → qq-bridge 管理的专用 qq-hardware DSH/DeepSeek 会话
  → 当前轮次授权的 hardware_reply
  → TopPet Qwen 合成、设备播放、字幕与表情
  → 设备完成 / 失败 / 打断回报
```

| 模块 | 职责 |
| --- | --- |
| qq-bridge | 身份绑定、人格、记忆、上下文装配、会话、消息路由、工具权限和审计 |
| DSH / DeepSeek | 沿用现有模型执行能力；硬件使用 `qq-hardware` 专用预设 |
| TopPet 主机 | 录音协议、Whisper、Qwen、字幕、设备协议、播放和打断 |
| 设备固件 | 麦克风采集、扬声器、屏幕、本地即时停止和动作回报 |

硬件新路径的 `BridgePipeline` 不创建 PetBrain、第二套聊天模型客户端或独立聊天记忆；失败也不回退到另一套大脑。原有声音与设备底层继续复用。

硬件输入默认只从硬件回答；QQ 输入默认只从 QQ 回答。不要求 QQ 遥控硬件，不默认双端重复播报。普通 DSH standard 会话手工调用工具不能替代本项目验收。

## 5. 身份、上下文、权限与重试

- 第一版只绑定现有 `ownerQQ` 对应用户和 `top-pet-01`。真实用户标识从本机配置读取，不在公开交接文件复制账号或凭据。
- 角色沿用桥接原有加载逻辑。实施验收时没有选中命名角色，使用当时桥接的默认提示与私聊背景；不能宣称某张自定义角色卡已真机验收。
- 硬件模型会话与 QQ 执行会话分开；每轮显式装配绑定私聊背景和该用户的个人记忆。硬件输入及设备确认完整播放的回复会提供给该用户后续 QQ 私聊。
- 仅导入绑定私聊中可验证属于该用户或机器人的记录；群聊与其他用户不会自动混入。个人长期记忆按 `QQ:<user>` 隔离。
- 硬件专用预设只允许回复、状态和个人记忆工具；执行期也有守卫。QQ 的工具权限没有因此统一开放硬件控制。
- 模型不能自行指定其他用户或设备。轮次凭据绑定当前任务，失效、取消或过期后禁止旧回复恢复播放。
- 新输入不等待 QQ 长轮询；取消只作用于所属硬件会话，不取消无关 QQ 任务。
- 输入按设备与录音会话去重，输出按稳定动作键去重。桥接重启不会自动重放未完成旧任务。
- `accepted`、合成完毕、发送完毕均不等于播放完成。匹配设备会话上报 `playback_finished` 才能记为 `playback_confirmed=true`；这仍不能代替人工确认听感。
