# TopPet 低延迟流式语音链路实测报告

测试日期：2026-08-23（Asia/Shanghai）

## 验收结论

本次改造已经把麦克风上传、LLM 分句、VoxCPM、WebSocket 下行和 ESP32 播放改成
真实流式流水线，完成代码、自动化测试、固件编译、COM5 烧录和 30 轮硬件链路测试。
但最终性能验收 **未通过**，不能宣称完成目标：

- 首声 P50：**2549ms**（目标不高于 1500ms）
- 首声 P95：**3535ms**（目标不高于 2200ms）
- 30/30 轮到达播放完成，0 崩溃、0 溢出、0 PCM 乱序、0 迟到会话帧
- 14/30 轮发生播放欠载，共 251 个欠载间隔（目标为 0）
- 独立 VoxCPM 首块满足门槛：选定 3 steps/prefix 2 的三档 P95 为
  324/157/155ms（门槛 800ms）

阻塞项有真实测量证据：30 轮中 LLM 首句 P95 为 2016ms；VoxCPM 热态曾以
11.137 秒生成 10.4 秒音频（RTF 1.071）。生成速度慢于播放速度时，要求的
100–160ms 初始缓冲必然耗尽。增大到约 500ms 可以缓解欠载，但会进一步恶化首声并
违反既定缓冲策略，因此没有用扩大缓冲伪造通过。

## 修改前后时序

修改前（已知基线）：

```text
GPIO18 松开
  -> 一次性上传完整 PCM
  -> 写临时 WAV
  -> Faster Whisper small / beam 5 完整识别
  -> 等待 LLM 完整回复
  -> VoxCPM model.generate() 生成完整 WAV
  -> 主机发送完整 WAV
  -> ESP32 开始播放
```

已实现链路：

```text
GPIO18 按下
  -> AudioCaptureTask 每 20ms 形成 640-byte PCM 帧
  -> NetworkTask 在长期 v2 WebSocket 上持续上传并校验 sequence
GPIO18 松开
  -> 内存 NumPy ASR（base/cpu/int8/zh/beam 1）
  -> LLM stream 回调 -> SentenceChunker -> asyncio.Queue
  -> 首句立即 POST /tts/stream -> VoxCPM generate_streaming()
  -> 跨块状态 48kHz -> 16kHz 重采样 -> v2 裸 PCM
  -> ESP32 16KB StreamBuffer，160ms 阈值后首个 I2S 写入
  -> 后续 LLM/TTS/网络发送与当前句播放并行
```

## 异常场景结果

- 主机服务重启：设备自动重连，恢复后继续新会话；过程中发现并修复 ping/pong 缺失。
- VoxCPM 客户端中断/超时：发现旧生成器跨 yield 持锁；改为独立生产线程后，即使
  HTTP 消费者消失，生成结束或取消都会释放 GPU 锁。服务取消单测通过。
- ASR 空结果：主机发 `INVALID_AUDIO_OR_TRANSCRIPT`，设备清理本轮 UI/播放状态。
- 快速新会话/迟到帧：自动化测试验证取消后旧 session 音频、字幕不会进入新 session。
- PCM 丢帧/乱序：自动化和 v2 WebSocket 测试验证错误事件、补静音和旧帧丢弃。
- 中途打断：主机/设备均已实现本地清空与 session 取消，自动化测试通过；本次 30 轮
  硬件矩阵未单独计入可审计的毫秒级物理打断样本，因此不能声称硬件 ≤200ms 已实测。
- Wi-Fi：30 轮期间 RSSI 约 -23 到 -51dBm，修复 pong 后长连接持续完成全部轮次；
  未主动关闭 AP 做可重复的断网时长实验。

## 未解决风险与下一步

1. **性能阻塞**：DeepSeek 首句 P95 2016ms 已几乎耗尽整条 2200ms 预算。需要更低延迟
   的 LLM 端点、同机小模型，或在按键期间有可靠 partial ASR 后提前启动 LLM。
2. **持续生成阻塞**：VoxCPM 热态 RTF 可大于 1。要在 160ms 首缓冲下做到零欠载，
   必须加速模型（更快 GPU/量化/更快声学模型）或改为能跨句保持生成状态的连续 TTS；
   单纯扩大设备缓冲只能交换首声延迟，不能同时满足本任务两个目标。
3. **硬件打断测量**：代码和自动化覆盖已具备，但仍需加入设备 `playback_aborted`
   时间戳并执行物理 GPIO18 打断样本，才能签署 ≤200ms。
4. **声学验收**：板载麦克风连续采集已验证，自动声学回放受测试现场扬声器位置/端点
   限制。应由人在设备前以正常音量补测识别准确率和最终扬声器听感。
