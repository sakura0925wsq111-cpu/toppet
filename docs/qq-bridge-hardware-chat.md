# 大肥鱼实体硬件聊天接入

本接入面向 `Derpyu520/qq-bridge`，不是普通 DSH 窗口里的硬件工具演示。实际链路为：

按键录音 → TopPet Whisper → qq-bridge 硬件入口 → 绑定用户、当前角色和私聊背景 → 桥接管理的 `qq-hardware` 会话 → 受限硬件工具 → Qwen → 原录音会话的扬声器、字幕和表情 → 结果回传。

## 启动与职责

本机入口为 `D:\toppet\start-companion.ps1`，它转发到活动 V2 工作树的同名脚本。完整启动脚本管理已安装 DSH 的本地后台、qq-bridge、TopPet 主机；通常无需进入 DSH 页面输入指令。切换旧 PetBrain 主机时首次运行可带 `-ReplaceLegacyHost`，只替换身份验证通过的旧主机，不结束其他程序。

```powershell
& D:\toppet\start-companion.ps1
```

该入口默认选择 `qq-bridge`。`BridgePipeline` 不创建 PetBrain、聊天客户端或独立记忆；识别后的文字只提交桥接，失败时不回退到另一套模型。现有 ASR、Qwen、连续 PCM、重采样、播放窗口和设备本地打断继续复用。

qq-bridge 负责用户身份、角色、记忆、上下文、DSH 会话和工具权限。一个设备绑定到现有 `ownerQQ`；角色通过桥接原来的读取函数取得。硬件会话独立于 QQ 的执行会话，但每轮显式注入绑定私聊的背景，并把硬件已接收的输入、设备确认完整播放的回复提供给该用户后续 QQ 私聊。群聊或其他用户不会自动混入。

## 数据与网络

- DSH 数据：`D:\dafeiyu\dsh-home`。
- 缓存、临时目录、后台日志：`D:\dafeiyu\runtime-data`。
- 桥接配置与历史：`D:\dafeiyu\qq-bridge\state` 和被 Git 忽略的本机配置。
- 本轮验证产物：V2 工作树的 `artifacts/`；不提交聊天、音频、令牌或模型凭据。

原 C 盘 DSH 数据保留未改；迁移后的后台通过安装自带的 DSH 引擎和已有配置运行 `companion` 服务配置，不打开浏览器，不创建 standard 演示会话。Python、HF、Torch、CUDA 和 Node 的任务缓存路径也指向 D 盘。

电脑保持 ZMGY。当前设备使用电脑的 `TopPet-Host` 2.4GHz 热点，主机网关为 `192.168.137.1:8765`。开启热点使用 `tools/start_hardware_hotspot.ps1`（Windows PowerShell 5.1），可加 `-Stop` 关闭。该操作不切换电脑 Wi-Fi。已实测当前代理 TUN 与电脑热点同时开启会导致 HTTPS 重置；保留普通 HTTP 代理并关闭 TUN 的组合可用。用户已选择关闭 TUN。没有公网映射、云部署或“两个网络都能上网就可互通”的假设。

## 回复、字幕与取消

硬件工具只能针对当前绑定用户、设备和本轮录音会话输出，不能选择其他用户或设备。短期凭据失效后，旧模型回调不能恢复音频。QQ 预设仍拒绝硬件工具；硬件专用预设只允许桥接的回复、状态和个人记忆工具，不允许 QQ 发送、QQ 长等待或本地执行。

硬件输入以设备和录音会话去重；模型回复以同一个任务键去重。桥接重启不自动重放旧任务。本地按键立即打断，桥接只取消自身硬件会话；QQ 任务不共用取消状态。未播完的回复不作为已说出写入共享对话。

长回复按实际字体宽度分页，不再把全文永久截成两行和省略号。为避免拆句破坏语调，Qwen 仍只合成一次完整回复；按实际 PCM 长度调度字幕页。硬件聊天目前先缓冲完整合成结果再连续下发，以减少生成抖动导致的断续，并限制过量排队音频；这会增加首声等待，不代表声音克隆或扬声器音质已完成优化。

短于两秒的录音补静音上下文、使用较稳健的解码设置，继续禁止第二次 VAD 抹掉短音节；日志记录录音时长、RMS 和峰值。离线生成的“你好、在吗、停一下”均经真实 Whisper 识别正确；这不等于真实麦克风的短句准确率验收。

## 验证边界与待办

真实按键语音已进入 qq-bridge，注入绑定私聊背景，使用 `qq-hardware` 预设调用硬件工具，并由在机设备回报播放完成。后来字幕、短句和稳定播放修复完成了相关 Python 单元/模拟测试；新的现场听感、字幕切换和短句起音仍待复测。

`accepted`、合成完成或发送完成不算用户已听到。`playback_confirmed=true` 是设备完整播放回报；人工听感、声学测量和屏幕观感是另外的验收层次。网络重连、取消和去重由单元/模拟测试覆盖，不能当作所有异常场景均已真机通过。

原 QQ 网关当前离线，保存的私聊背景可用，实时 QQ 收发仍待网关上线复测。QQ 审计包括模式隔离、发送白名单、队列、等待、角色、记忆和协议回归；缺失的独立 voice-tool、ffmpeg 可选段或真实网关测试须明确区分跳过与通过。

可运行：`tests/test_bridge_pipeline.py`、`tests/test_hardware_caption_pages.py`、`tests/test_hardware_control.py` 及既有设备/播放回归。qq-bridge 运行 `npm run test:hardware` 和 `npm run test:audit`。上游只读时，本功能的 qq-bridge 提交补丁随 `integrations/qq-bridge/` 备份；不携带本机配置、历史、凭据、声线素材或运行目录。
